# 统一 App 多 Agent 本机验证

日期：2026年10月26日，Asia/Shanghai。开发版0.2.0，macOS27 arm64。原生 App 已安装在 `/Applications/ApplePersonalMCP.app`。npm 包及 Node 入口已删除，无全局 npm 安装需要卸载。

## 实际通过

`Scripts/multi-agent-smoke.py` 通过已安装签名入口建立两个真实 stdio MCP 客户端，共享同一个用户 XPC 宿主。临时 Agent 分别授予 mail.read 与 mail.read/mail.write，没有 send 权限。

| 验证 | 结果 |
| --- | --- |
| 独立客户端 | 两个独立入口进程、不同凭据；展示的工具权限不同 |
| 读者越权 | 读者直接调用缓存的创建草稿工具被 permission_denied 拒绝，未创建邮件 |
| 实际读取 | 两个 Agent 读到6个账户、36个邮箱 |
| 真正并行 | 两个 Agent 各执行两次100候选正文扫描；宿主活动开始/结束区间确认跨 Agent 读取重叠 |
| 真实资源隔离 | A导出已下载附件并可读取；B用同一个 asset_id 读取得到 not_found |
| 动态降权 | 已连接B改为calendar.read后，新的工具列表不含Mail，缓存Mail查询被拒绝，状态不泄漏Mail消息数 |
| 动态撤销 | B保持连接时撤销，其下一次system_status被invalid_credentials拒绝 |
| 重启保持 | 关闭客户端并重启用户宿主后，A原凭据仍可用，B撤销记录保持 |
| 邮件回归 | 原smoke通过认证入口完成账户、邮箱、正文、未读保持、线程、批量、正文扫描及2,608,746字节附件导出验证 |
| 旧入口拒绝 | 不带凭据运行原生doctor，退出1并提示credentials_required |

本轮未外发邮件，也未修改真实邮件。临时验证 Agent 均已撤销，凭据文件和它们的导出副本已清理；注册表保留撤销状态。日志只有ID、工具、阶段和耗时，不包含正文或密钥。

## 测试与限制

最终完整测试27项通过。包括队列受控测试（读取重叠、Mail自动化串行、四路读取上限及单Agent16请求限制）、排队后撤销/断开拒绝、跨Agent/应用附件授权、operation记录查询隔离，以及跨Agent/旧版本操作ID继续全局唯一、unknown状态不被其他Agent改写。真实自动化写入并发未再次修改邮件，串行性证据来自受控测试；不把它描述为真实邮件写冲突压力测试。

原生Agent管理界面已实现创建、修改权限、复制配置和撤销。已通过实际窗口AX和截图核验六应用权限、管理按钮和布局；打开App会转发到实际后台宿主显示窗口，旧界面进程已重启。创建/降权/撤销的实测走本机管理命令和同一注册表，不把窗口显示核验等同于逐按钮操作测试。

后续五应用的读取已继续实现并实际验证，详见[六应用读取记录](2026-10-26-six-app-reads.md)。修改、发送、录音控制等不属于本次读取通过的结论。

同用户完整shell权限不在本服务授权隔离的防御范围；管理命令只供本机所有者使用，不暴露到MCP。队列只协调本服务，不能阻止系统App或其他程序并发改动。撤销阻止排队和后续操作，不能撤回已发生的副作用。
