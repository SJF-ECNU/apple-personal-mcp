# 设计

## Decisions

App 创建 UUID Agent ID 和系统随机 256 bit 凭据，存入用户专属 SQLite（0600，目录0700），客户端配置文件同为0600，仅返回路径，不写入日志。无自定义 Hash。数据库唯一主键和事务处理增改；客户端 identity.name 不参与认证。此权限边界属于 MCP 服务，不是针对同一用户完整 shell 能力的沙箱。

权限使用六应用的 read/write，以及 mail.send/messages.send；write 需要 read，send 需要 write。未实现模块的授权不代表该模块可用。管理界面和宿主本机管理命令修改授权；管理接口不暴露给 MCP。撤销不可复用旧凭据。每次 tools/list 和调用重新检查，不使用会话缓存权限。

每个 XPC 连接独立 endpoint，会话在首次请求绑定 Agent。请求在入队与执行时认证；断开后排队任务不再启动。读取四路并行，官方自动化（含读取草稿）按应用单队列，保证 Mail 脚本调用不交错；读取结果返回前复查权限，发邮件确认后再次复查。已经发生的外部效果不能因撤销而回滚。

每请求创建 MailModule/数据库连接，不跨并发请求共享缓存连接。写队列仅协调本服务请求，不能阻止 Mail UI 或其他程序修改。现有对象读回检查保留，不宣称并发原子编辑。

附件使用Agent UUID及应用子目录，assets_read逐次验证对应应用读权限。发送operation使用全局SQLite的唯一主键和owner列，查询按Agent隔离；升级前无owner记录保持未归属，但ID继续阻止重发。普通迁移事务添加列，不丢弃旧记录。旧共享资源不再暴露。活动记录含Agent/连接/请求ID和工具阶段、耗时，不记录凭据和内容。

打开App时通过仅接受原生App签名的owner XPC通道显示后台宿主管理窗口，避免多个界面进程持有不同授权状态。EventKit与Notes授权由实际后台宿主发起，MCP桥接签名不能调用该通道。

## Validation

合成测试验证认证、跨应用权限、撤销/降权、跨 Agent 资源及 operation 隔离；受控并发测试证明读取重叠、自动化串行、读取不被写队列阻塞、排队撤销不执行。安装签名 App 后，以两个真实 stdio MCP 客户端验证工具目录、权限错误、并发读取、动态撤销和服务重启后的保持。
