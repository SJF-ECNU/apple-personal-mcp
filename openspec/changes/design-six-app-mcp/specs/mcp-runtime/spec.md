## ADDED Requirements

### Requirement: 本地原生宿主与协议入口

系统 SHALL 通过 stdio 提供 MCP，使用原生用户会话宿主执行六应用操作，并在跨进程入口验证用户及系统代码签名身份；协议 stdout SHALL 不含诊断文本。

#### Scenario: 正常客户端连接
- **WHEN** 用户已完成宿主设置且 Agent 启动随包入口
- **THEN** 客户端可以协商受支持的 MCP 版本并列出明确的工具和资源能力

#### Scenario: 未授权的对端连接
- **WHEN** XPC 对端不满足用户或代码签名要求
- **THEN** 宿主拒绝该连接且不返回个人数据

### Requirement: 权限与能力按应用独立报告

系统 SHALL 区分权限拒绝、未配置、不支持和暂时不可用；工具实际执行仍 SHALL 处理权限撤销，不能用状态探针替代真实调用。

#### Scenario: 录音读取无权限
- **WHEN** 宿主无法打开录音源但 EventKit 可用
- **THEN** 录音能力报告需要授权，日历工具仍可以工作

#### Scenario: 授权被撤销
- **WHEN** status 检查后用户撤销某应用访问
- **THEN** 实际调用返回该应用的权限错误而非空数据

### Requirement: 完整正文与有界传输

系统 SHALL 为长正文、查询和资源提供可继续读取方式，明确正文完整性和本地覆盖范围；不能静默截断全文。

#### Scenario: 长文本跨多页
- **WHEN** 一份转写超过单次响应限制
- **THEN** 客户端可通过游标重组全文，末页明确无后续，且文字不会因编码边界丢失

### Requirement: 发送结果未知时不重发

系统 SHALL 对外部发送使用带唯一约束的操作 ID，区别已提交、失败和未知；重复操作 ID SHALL 只返回既有执行状态，不能重发或修改原目标。

#### Scenario: 提交后连接断开
- **WHEN** 系统调用 send 后无法确定结果
- **THEN** 操作标记 unknown，重连或超时重试不再次调用 send

#### Scenario: 已有明确授权
- **WHEN** 用户在原生设置中授予的限定授权仍覆盖目标与动作
- **THEN** 服务可在范围内执行而不重复询问；Agent 自填 confirmed 参数不产生新授权

### Requirement: 长任务独立于协议扩展

系统 SHALL 使用普通工具返回和查询 job ID；取消与重启 SHALL 如实保留已发生效果和未完成状态。

#### Scenario: 宿主重启
- **WHEN** 转写任务未完成时宿主退出并重启
- **THEN** 任务标记 interrupted，不被描述为已经成功或具备未实现的断点恢复

### Requirement: 只读模式双重限制

系统 SHALL 在 --read-only 模式下不列出应用修改工具，并在实际分发时拒绝缓存的修改调用；受限资源导出仍可用，生成转写和录音控制不在此模式开放。

#### Scenario: 客户端使用旧工具目录
- **WHEN** 客户端在只读模式调用此前缓存的 mail_send_draft
- **THEN** 明确拒绝，不因客户端记得工具名而执行发送

### Requirement: 直接诊断与工具执行

系统 SHALL 提供共用服务实现的 CLI doctor 与 call 入口，不因绕开模型调用而绕过授权；诊断区分读取与修改通道及实际版本，对不确定的授权归属不能假称精确。

#### Scenario: 读取可用但修改未授权
- **WHEN** 本地 Mail 数据可读而 Automation 未授权
- **THEN** doctor 分别展示两个状态，CLI call 与 MCP 调用执行相同授权检查

### Requirement: 调用阶段与可选工作流

系统 SHALL 在调用开始和结束记录无正文的活动元数据与实际运行版本，并能区分等待、执行及读回；工作流示例只能经用户或 Agent 显式调用，不自动运行。

#### Scenario: 执行中崩溃
- **WHEN** 官方操作开始后宿主崩溃而没有完成记录
- **THEN** 状态仍可显示请求已开始且结果待核对，不能把它当作从未收到

#### Scenario: 查看工作流示例
- **WHEN** 用户读取邮件回复草稿或录音待办示例
- **THEN** 只取得调用指导，不自动发送、创建待办或安装全局 Skills
